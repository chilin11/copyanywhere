## 结论摘要

**1. 最可能的原因不是「同步慢」，而是「两台设备不在同一个空间」（假设 H1，待验证）。**
现有设计里，任何让浏览器「没有密钥」的情况（iPhone 添加到主屏幕、换浏览器扫码、链接被截断、服务器返回 404）都会把用户带到一个只有「创建空间」按钮的页面；新建之后两端都显示「已连接」，界面上没有任何东西能看出它们是两个空间。验证只需一条命令（01 篇 D1）。

**2. 即使在同一空间，现有同步也有三处代码可证实的不可靠点。**
实时通道没有可见心跳和兜底轮询（流静默时无限期看不到新内容，C6）；快照与事件之间没有版本号（偶发把刚到的条目删掉，C5）；手机端小内容发送没有重试、失败只有 4 秒提示、分享入口会误报成功（C7、C8）。

**3. 方案的四个支点。**
- **看得见**：空间指纹 + 在线设备数常驻顶栏；发送后明确告知「另有 N 台在线」或「当前没有其他设备在线」。
- **收得到**：每空间 `rev` + 进程 `epoch`，心跳携带 `rev`；漏掉的变更最迟一个心跳周期内自愈；流不通时自动降级为轮询。
- **发得出**：客户端生成条目 id 实现幂等重试；发件箱状态机，失败常驻可重试，文字可取回。
- **查得清**：错误码、空间诊断接口、流回环自测、不含隐私的事件日志、客户端诊断面板。

**4. 兼容性。**
不改加密算法、密钥格式、配对链接、磁盘格式；无数据迁移；所有接口为增量；v2 事件流显式启用，已打开的旧页面继续按 v1 工作；可随时回滚。

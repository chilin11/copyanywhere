# 03 · 用户流程与界面设计（移动端 / 桌面端）

本篇给前端与设计验收用。文案均为最终中文文案；状态名与 02 篇一致。
未做的事：没有出视觉稿，没有在真机上验证过任何布局；下文是结构、行为与文案规范。

## 1. 设计原则

1. **先回答三个问题**：我在哪个空间？对面在不在？刚才那条发出去了吗？这三件事必须常驻可见，不靠 toast。
2. **状态说真话**：只显示能证实的事实（「已保存到服务器」「另有 1 台设备在线」），不显示无法证实的（「对方已收到」）。
3. **失败不消失**：任何失败都留在界面上直到用户处理；文字永远可取回。
4. **手机单手可用**：主要操作在屏幕下半区，触控目标 ≥ 44×44 px，按钮带文字。
5. **最新的在最上面**：这是剪贴板历史而不是聊天，接收方最常做的事是「复制最新一条」。两端一致。

## 2. 用户流程

### 2.1 第一台设备：创建空间
1. 打开域名 → 首屏两个并列入口（见 §3.1）：**加入已有空间**（默认聚焦）与 **创建新空间**。
2. 选「创建新空间」→ 输入服务器密码 → 创建成功 → 进入主界面并自动弹出「添加设备」。
3. 「添加设备」对话框顶部显示本空间指纹，如 **空间 K7QM**，并提示：「另一台设备加入后，顶部也会显示 K7QM」。

### 2.2 第二台设备：扫码或打开链接加入
1. 扫码/打开链接 → 页面读取片段中的密钥并立即从地址栏移除。
2. 本机**没有**密钥：校验空间存在 → 直接进入，顶部显示同一个指纹；第一台设备的在线数从 1 变 2，并提示「新设备已加入：现在 2 台设备在线」。
3. 本机**已有不同**密钥：走 §2.7 的确认。
4. 链接格式不对（被截断/多了字符）：停在首屏，红字提示「这个配对链接不完整。请在已加入的设备上点『添加设备』→『复制链接』，再粘贴到下面。」现有密钥不受影响。

### 2.3 粘贴链接加入（iPhone 主屏幕 App、换了浏览器）
1. 已加入的设备（或同一台手机的 Safari）：顶栏空间条 →「添加设备」→「复制链接」。
2. 目标环境（主屏幕 App / 另一个浏览器）首屏「加入已有空间」→ 点「粘贴配对链接」按钮（调用剪贴板读取；失败则聚焦输入框让用户长按粘贴）。接受完整链接或单独的 43 位密钥。
3. 校验通过 → 进入。输入框使用 `type="password"` 外观并在成功后清空，避免密钥留在屏幕上。
4. iPhone Safari 中（非主屏幕模式）首次进入空间后，显示一次性提示条：「要添加到主屏幕？添加后第一次打开需要再粘贴一次配对链接。〔复制配对链接〕〔知道了〕」。

### 2.4 发送
1. 输入文字点发送 / 点「粘贴并发送」/ 选照片文件 / 从系统分享菜单进入。
2. 输入区上方立刻出现发件箱卡片：`加密中… → 上传 42% → 已保存`。输入框在卡片出现后才清空。
3. 成功：卡片变为一行 2 秒的确认条后收起，条目出现在列表顶部并高亮；确认条文案二选一：
   - 「✓ 已保存 · 另有 1 台设备在线」
   - 「✓ 已保存 · 当前没有其他设备在线 〔对方看不到？〕」
4. 可重试的失败：卡片显示「网络不稳定，3 秒后第 2 次重试 〔立即重试〕〔取消〕」。
5. 最终失败：卡片常驻，红色，「发送失败：<原因> 〔重试〕〔取回文字〕〔丢弃〕」（文件类没有「取回文字」）。

### 2.5 「对方看不到？」自查
入口：发送确认条、顶栏空间条、空状态、设置。一个底部抽屉（手机）/ 对话框（桌面），三步，每步都有本机的实时判定：

| 步骤 | 本机显示 | 引导 |
|---|---|---|
| ① 是不是同一个空间 | 「本机空间：**K7QM**」 | 「看另一台设备顶部的空间代号。不一样 → 在这台设备上点〔复制配对链接〕，到另一台粘贴加入。」 |
| ② 对方在线吗 | 「当前在线：2 台」或「只有本机在线」 | 「只有本机 → 另一台没打开页面，或不在这个空间。」 |
| ③ 实时通道通吗 | 「实时同步正常（往返 38 ms）」/「实时通道不通，已改为每 5 秒同步」 | 「不通通常是反向代理缓冲了事件流，内容仍会在几秒内出现。〔复制诊断信息〕发给管理员。」 |

### 2.6 空间不存在
仅在服务器明确返回 `space_not_found` 时出现（02 篇 §4.7），整页提示而不是静默跳回创建页：

> **服务器上找不到这个空间（K7QM）**
> 可能是空间被删除，或服务器数据被重置。本机的钥匙还在，没有被清除。
> 〔重试〕　〔粘贴新的配对链接〕　〔在本机移除这个空间〕

「创建新空间」放在次要位置并加一句：「其他设备需要重新扫码加入新空间。」

### 2.7 切换空间确认
本机已有空间 A，又打开了空间 B 的链接：

> **要切换到另一个空间吗？**
> 当前：空间 **K7QM**　→　链接指向：空间 **3FWD**
> 切换后本机将不再能看到 K7QM 里的内容，除非重新用它的配对链接加入。
> 〔保持当前空间〕（默认）　〔切换到 3FWD〕

目标空间校验失败时不弹此框，只提示「链接指向的空间不存在，已保持当前空间」。

### 2.8 接收与复制
- 新条目出现在列表顶部，高亮 2.4 秒；页面在后台时标题显示未读数（保留现有行为）。
- 当前筛选会隐藏该条目时，筛选条下方出现提示条：「有 1 条新的图片 〔查看〕」，点击切到对应筛选并滚动到顶。
- 用户已向下滚动时，顶部浮出「↑ 1 条新内容」胶囊，点击回到顶部。
- 每条的主操作只有一个且在卡片左下、最大：文字「复制」、图片「复制图片」、文件「下载」。删除收进「⋯」菜单，避免误触。

### 2.9 连接异常
顶栏状态胶囊随 02 篇 §6.1 的状态变化；点击胶囊打开 §2.5 的自查面板。进入 `offline`/`degraded` 超过 10 秒时在列表顶部显示一条不遮挡内容的说明条，恢复后自动消失。

## 3. 界面结构

### 3.1 首屏（两端相同，单列，最大宽 440 px）
```
            CopyAnywhere
     随处复制，随处粘贴

 ┌───────────────────────────────┐
 │ 加入已有空间                   │
 │ 在已加入的设备上点「添加设备」  │
 │ 扫码，或把配对链接粘贴到这里：  │
 │ ┌───────────────────────────┐ │
 │ │ ••••••••••••••••          │ │
 │ └───────────────────────────┘ │
 │ [ 粘贴配对链接 ]   [ 加入 ]    │
 │ （错误提示行）                 │
 └───────────────────────────────┘
 ┌───────────────────────────────┐
 │ 创建新空间  ▸（默认折叠）      │
 │ 第一台设备才需要。服务器密码： │

 非 HTTPS / 浏览器不支持加密时：整页只显示

```

- 底部区域用 `position: sticky/fixed` + `env(safe-area-inset-bottom)`；软键盘弹出时跟随 `visualViewport` 上移，三个大按钮在键盘弹出时收起为输入框左侧的一个「＋」。
- 存储用量条移入设置面板（手机上不占主界面）。
- 空状态：大字「还没有内容」+ 一句「在任意设备发送，这里立刻出现」+ 空间指纹与在线数 +〔添加设备〕按钮。

- 拖拽蒙层文案不变：「松开即可加密发送」。

### 3.4 添加设备对话框
```
添加设备                         空间 K7QM
┌──────────┐  1. 用另一台设备的相机扫码
│   二维码  │  2. 或复制链接，在那台设备的首屏粘贴
└──────────┘  3. 加入后，对方顶部也会显示 K7QM

```
对话框打开期间在线数实时更新；从 1 变 2 时显示「✓ 新设备已加入」。

### 3.5 设置面板
分三组：**本机**（设备名、收到文字自动复制）、**空间**（指纹、在线数、存储用量、添加设备、清空全部内容）、**排障**（连接诊断、对方看不到？）。危险操作单独置底：本设备退出、删除整个空间（文案与确认沿用现有）。

## 4. 组件状态与文案

### 4.1 顶栏状态胶囊
| 状态 | 图标/颜色 | 文案 | 点击后说明 |
|---|---|---|---|
| connecting | 黄色脉冲 | 连接中… | — |
| live | 绿色实心 | 实时同步 | 「新内容会立刻出现。」 |
| degraded | 黄色半圆 | 轮询同步 | 「实时通道暂时不通，每 5 秒同步一次。」 |
| offline | 红色空心 | 离线 | 「网络恢复后会自动同步，待发送的内容会自动重发。」 |

### 4.2 空间条
`空间 K7QM · N 台在线`。`N = peers`；`N = 1` 时显示「只有本机在线」并用次要色。指纹字符使用等宽字体，颜色由指纹哈希取色相（与设备头像同一算法），两台设备一眼可比。

### 4.3 发件箱卡片
| state | 展示 | 操作 |
|---|---|---|
| queued | 「等待中」 | 取消 |
| encrypting | 「加密中…」 | 取消 |
| uploading | 进度条 +「上传 42% · 1.2 MB/s · 剩余 8 秒」 | 取消 |
| waiting | 「网络不稳定，N 秒后第 k 次重试」 | 立即重试 / 取消 |
| failed | 红色，「发送失败：<原因>」 | 重试 / 取回文字 / 丢弃 |
| committed | 绿色确认条 2 秒（§2.4-3） | — |

`<原因>` 映射（按 02 篇 §4.7 的 `code`）：`too_large`→「超过大小上限 X」；`disk_full`→「服务器磁盘已满，请联系管理员」；`storage_busy`→「服务器正忙于其他上传」；`space_not_found`→「空间不存在」；网络层→「网络连接失败」；其余→「服务器错误（<code>）」。

### 4.4 列表条目
保留现有三种卡片的视觉区分。调整：主操作按钮放大并固定在左下；删除收入「⋯」；「本机」标签保留；解密失败的条目显示为占位卡「无法解密的内容（1）」而不是消失。

## 5. 视觉与可达性约束
- 所有输入控件字号 ≥ 16 px（避免 iOS 聚焦缩放）。
- 触控目标 ≥ 44×44 px；手机端按钮必须带文字，不允许仅图标（设置齿轮、关闭除外，且需 `aria-label`）。
- 状态不只靠颜色区分：胶囊同时有形状（实心/半圆/空心）与文字。
- 状态胶囊、发件箱用 `aria-live="polite"`；失败卡片用 `role="alert"`。
- 沿用现有色板与深浅色变量；不引入外部字体、图片或内联样式（CSP 不放宽）。
- `prefers-reduced-motion` 下取消高亮与脉冲动画（沿用现有规则）。
